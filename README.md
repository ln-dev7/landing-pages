# Shadcn Pages Free

Open-source **shadcn/ui landing page templates** with a personality of their own.
Built with Next.js, Tailwind CSS and fully customized shadcn/ui. Free to use, MIT licensed.

**[Explore the collection →](https://lp.lndev.me)**

Shadcn Pages Free is the open-source side of **Shadcn Pages**: every template is a complete Next.js project you can
clone, run and make your own.

## Run locally

Each folder in `landing-pages/` is an independent project.
Requires **Node.js 20.9+** and **pnpm**. From the repository root:

```bash
cd landing-pages/fallow # or another project
pnpm install
pnpm dev
```

For a production build, run `pnpm build`, then `pnpm start`.
See each project's README for its configuration.

## Showcase

`www/` is the collection website, built with HTML, CSS and JavaScript: the collection on `/` (`projects.js`) and the
community pages on `/community` (`community.js`). No dependencies or build step.

Shadcn Pages Pro is prepared but hidden: `www/pro.js` holds `live: false`. Setting it to `true` adds a Pro link to the
header (in place of "The idea") and the footer, the "Need the whole site?" section after the collection (covers in
`www/showcase/pro/`), and a "The full site, every page" link on the free pages listed in `fullSites`. The header logic
for Community and Pro lives in `www/site-nav.js`. From the repository root:

```bash
cd www
python3 -m http.server 8000
```

## Deploy

On Vercel, create a separate project for each site:

| Site | Root Directory | Framework preset |
| --- | --- | --- |
| Landing page | `landing-pages/<project>` | Next.js |
| Collection showcase | `www` | Other — no build step |

Each project’s `vercel.json` skips builds when its folder is unchanged since its previous deployment. The first deployment always builds.

## Contribute

Made a landing page you want to share? Community pages live in `community/<slug>` and are listed on
[lp.lndev.me/community](https://lp.lndev.me/community) with their author. **One landing page per pull request.**
Read [CONTRIBUTING.md](CONTRIBUTING.md) before opening one.

Publishing a merged community page (maintainer):

1. Deploy it on Vercel: a new project with Root Directory `community/<slug>` (the domain `<slug>-community.vercel.app`
   is the default the site expects).
2. Add a 1600×900 screenshot as `www/showcase/community/<slug>.jpg`.
3. Add its entry at the top of `window.COMMUNITY` in `www/community.js` (the fields are documented at the top of the
   file). The page sorts, numbers and counts entries by itself, and shows an empty state while the list is empty.
